# PHASE 10 — AI OPERATIONS COPILOT & INTELLIGENT RECOMMENDATIONS

This document outlines the architecture, intent parsing, data selection pipelines, and validation outcomes of the Operations Copilot layer implemented in Phase 10.

---

> [!IMPORTANT]
> **Operational Intelligence Disclaimer**:
> Phase 10 is a **telemetry-grounded operational intelligence layer**.
> It is strictly deterministic, referencing actual assessments generated by dashboard engines in real-time, and is configured as a future-ready abstraction for secure LLM integration.

---

## 1. Copilot Architecture

The assistant maps natural operator questions to localized telemetry arrays and calculations:

```
User Question (String)
         ↓
Intent Detection (copilotEngine.js)
         ↓
Context Builder (copilotContext.js payload)
         ↓
Evidence Selection (CopilotEvidence mapping)
         ↓
Response Generation (structured reply with actions & confidence tags)
         ↓
Dashboard UI (OperationsCopilot.jsx conversation box)
```

---

## 2. Context Builder & Intent Mapping

### A. Context Schema (`copilotContext.js`)
Builds a minimal structured payload containing current sensor parameters and assessor values:
* `telemetry`: current ambient temperatures, dynamic vibrations, active power draws.
* `energy`: accumulated Wh, average power, stability percentages.
* `health`: score rating, alarm status, checklist.
* `maintenance`: prioritized recommended inspections.
* `sustainability`: carbon equivalents and grid factors.
* `alerts`: count and types.

### B. Intent Parsing Matrix (`copilotEngine.js`)
* `EQUIPMENT_STATUS`: Answers questions regarding condition, score, and operational checks.
* `ENERGY`: Answers Wh totals and coverage rates.
* `ELECTRICAL`: Evaluates INA219 valid flags, voltage, current, and active power draws.
* `VIBRATION`: Explains dynamic gravity-filtered MPU6050 vibration deviations.
* `TEMPERATURE`: Explains DS18B20 and microchip core temperatures.
* `MAINTENANCE`: Outlines diagnostic action items.
* `SUSTAINABILITY`: Answers carbon footprint estimates and grid factors.
* `ALERTS`: Identifies active warning and critical alarms.
* `DATA_QUALITY`: Explains validation rates and missing telemetry gaps.

---

## 3. Data Integrity & Clamping
* **No Telemetry Overlap**: The engine consumes already computed dashboard memo parameters, preventing redundant database polling.
* **No Causal Speculation**: If trends show spikes, the assistant reports the correlation objectively: "The available telemetry does not establish the physical cause."
* **Clamped Metrics**: If electrical validity is false, it flags data as `INVALID` or `UNAVAILABLE`, displaying configuration alerts.
